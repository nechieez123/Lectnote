# Как работать с Git в проекте Lectnote

Эту инструкцию достаточно настроить один раз, дальше работа идёт по одному и тому же порядку.

## Один раз

1. Установи Git с сайта git-scm.com. Все настройки при установке оставь по умолчанию.
2. Прими приглашение в репозиторий: на почте письмо от GitHub, нажми **Accept invitation**.
3. Открой **Git Bash** (найди в меню «Пуск») и представься. Имя и почту пиши такие же, как на GitHub:
```
git config --global user.name "Имя Фамилия"
git config --global user.email "твоя_почта@example.com"
```
4. Скачай проект:
```
cd Documents
git clone https://github.com/nechieez123/Lectnote.git
cd Lectnote
```
При первой отправке изменений откроется окно входа в GitHub. Войди через браузер.

В Git Bash вставка делается через **Shift+Insert** (Ctrl+V не работает).

## Для каждой задачи

1. Обнови проект и создай свою ветку:
```
git checkout develop
git pull
git checkout -b feature/название-задачи
```
2. Сделай работу в своей папке (`api/`, `web/` или `docs/`).
3. Сохрани и отправь:
```
git add .
git commit -m "feat: что сделано"
git push -u origin feature/название-задачи
```
4. Открой pull request: ссылку покажет терминал после `git push`, либо зайди в репозиторий на GitHub и нажми жёлтую кнопку **Compare & pull request**. Проверь, что стоит **base: develop**. В правой колонке выбери **Reviewers** (кто-то другой из команды) и нажми **Create pull request**.
5. Проверяющий открывает вкладку **Files changed**, нажимает **Review changes**, выбирает **Approve** и после этого **Merge pull request**.

## Правила

- В `main` и `develop` напрямую ничего не отправляем, только через pull request.
- Начало сообщения коммита: `feat:` (новое), `fix:` (исправление), `docs:` (документы).
- Пароли и файл `.env` в репозиторий не добавляем.
- Предупреждения про LF и CRLF можно игнорировать.
- Каждый работает в своей ветке, чтобы не мешать остальным.
- Если появилась ошибка, скопируй текст из терминала и отправь его в чат команды.
