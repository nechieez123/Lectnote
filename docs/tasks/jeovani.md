## 1. Проверка ERD (до 17.10)

Илока нарисовал черновик ERD и открыл pull request. Нужно проверить, что в схеме есть всё, что нужно сценариям.

**Как сделать:**

1. Открой ссылку на pull request, которую пришлёт Илока, и перейди на вкладку **Files changed**.
2. Посмотри `erd.png`, `erd.md` (схема рисуется на самом GitHub) и `schema.sql`.
3. Открой `use-cases.md`. Для каждого шага каждого сценария спроси: «В какой таблице и в каком поле хранятся эти данные?» Если ответа нет, оставь комментарий: нажми значок **+** слева от нужной строки.
4. Нажми **Review changes** (кнопка справа вверху). Выбери **Approve**, если всё в порядке, или **Request changes**, если нужны правки.

**Результат:** pull request проверен и одобрен или возвращён с комментариями.

## 2. Встреча 16.10

На встрече нужно решить вопросы D-01…D-07 из `docs/business-rules.md` (раздел 3) и вопрос об удалении заметок и блоков (раздел 4, пункт 1).

## 3. Контракты API (16–19.10, вместе с Илокой)

**Что это:** список адресов (endpoint-ов), которые сервер даёт интерфейсу. Для каждого описывается: метод, адрес, что отправляет интерфейс, что отвечает сервер и какие бывают ошибки. Интерфейс и сервер договариваются об этом заранее, чтобы потом данные совпали.

**Как сделать:**

1. Создай файл `docs/api-contracts.md`. Для каждого адреса используй такой шаблон:
```
### POST /api/auth/login
Сценарий: UC-01
Запрос: { "email": "...", "password": "..." }
Ответ 200: { "token": "..." }
Ошибки: 401 — неверная почта или пароль
```
2. Опиши все адреса из этого списка (это стартовый вариант, дополняйте вместе с Илокой):

| Сценарий | Метод и адрес |
|----------|---------------|
| проверка связи | GET /api/hello |
| UC-01 | POST /api/auth/register, POST /api/auth/login |
| UC-02 | GET /api/courses, GET /api/courses/{id}/lessons |
| UC-03, UC-06–08 | POST /api/notes, GET /api/notes, GET /api/notes/{id}, GET и PUT для блоков заметки, добавление и удаление соавторов |
| UC-04 | POST /api/notes/{id}/audio |
| UC-05 | GET /api/transcription-jobs/{id} |
| UC-09 | POST и GET для комментариев к блоку |
| UC-10 | GET /api/notifications, PATCH /api/notifications/{id}/read |

3. Коды ошибок бери из `docs/business-rules.md` (там для каждого правила указаны 401, 403, 404, 413, 415 и другие).
4. Когда таблица готова, перенеси её в формат Swagger. Открой editor.swagger.io, опиши адреса в формате OpenAPI и сохрани результат как `docs/openapi.yaml`.
5. Отправь изменения в ветке `feature/api-contracts`, pull request в `develop`.

**Результат:** черновик Swagger (`docs/openapi.yaml`) и `docs/api-contracts.md`.

## 4. Презентация и проверка (21–24.10)

- Проверь pull request-ы команды, собери замечания.
- Подготовь презентацию. Структура защиты: 1. контекст приложения, 2. принцип работы, 3. демонстрация функций, 4. вопросы и ответы.
- Подготовь перевод, если он нужен для защиты.
- Убедись, что каждый участник может объяснить свою часть и общую архитектуру: преподаватель задаёт случайные вопросы.
