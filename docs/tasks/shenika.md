## 1. Kanban-доска и чат

**Как сделать:**

1. Открой репозиторий на GitHub, вкладка **Projects**, кнопка **New project**, шаблон **Board**.
2. Колонки: **Backlog, To Do, In Progress, Review, Done**.
3. Создай карточки для всех задач из плана работ. У каждой карточки должны быть исполнитель (**Assignees**) и срок. Если поля срока нет, добавь его: **+ → Date**.
4. Убедись, что в проект добавлены все четверо участников.
5. Если группового чата нет, создай его. Каждый день в чате все пишут коротко: что сделал, что делаю, что мешает.

**Результат:** все карточки с исполнителем и сроком, ссылка на доску отправлена в чат.

## 2. docker-compose для всего проекта (до 18.10)

**Цель:** весь проект запускается одной командой `docker compose up` на ноутбуке преподавателя (Arch Linux, 8 ГБ памяти). Поэтому контейнеры делаем лёгкими.

**Что понадобится:** Docker Desktop (docker.com).

Илока уже сделал базовый `docker-compose.yml` с базой данных PostgreSQL. Твоя задача: добавить в него `api` и `web`.

**Как сделать:**

1. Создай ветку:
```
git checkout develop
git pull
git checkout -b feature/docker-compose-full
```
2. Проверь, что база запускается:
```
cp .env.example .env
```
Открой `.env` и замени `change_me` на пароль. Затем:
```
docker compose up -d
docker ps
```
В списке должен быть контейнер `lectnote-db`.
3. Когда в папке `api/` появится `Dockerfile` (Илока сделает к 18.10), а в `web/` будет `Dockerfile` от Манучехра, добавь в `docker-compose.yml` в раздел `services:` два сервиса:
```
  api:
    build: ./api
    depends_on:
      db:
        condition: service_healthy
    environment:
      ConnectionStrings__Default: Host=db;Port=5432;Database=${POSTGRES_DB};Username=${POSTGRES_USER};Password=${POSTGRES_PASSWORD}

  web:
    build: ./web
    ports:
      - "8080:80"
    depends_on:
      - api
```
Названия переменных и порт API уточни у Илоки.
4. Чтобы страница обращалась к API через тот же адрес, в `web/` нужен файл `nginx.conf`. В нём адреса `/api/` направляются в контейнер `api`. Договорись с Манучехром, кто его добавляет.
5. Добавь в `README.md` инструкцию запуска (3–4 строки): скопировать `.env.example` в `.env`, задать пароль, выполнить `docker compose up`.
6. Отправь работу (команды из `git-guide.md`) и открой pull request в `develop`.

**Результат:** всё запускается одной командой, инструкция лежит в README.
